# Project Brief for Copilot Agent: Leakage-Free Temporal RAG for Financial Market Intelligence

## How to use this file
Put this file in the repo root. Tell the agent: "Read COPILOT_PLAN.md fully. Implement ONE phase at a time. After each phase, run its acceptance checks, commit, and stop for my review before starting the next phase."

## 0. Project summary
Build a Temporal RAG (T-RAG) system for financial news. Every query carries an `as_of` date. Documents with `publish_time > as_of` must be removed **inside the database query**, so they never reach the LLM. The system also provides sentiment timelines, event-study abnormal returns, and a verifier. It is compared against two baselines using a leakage test and a temporal QA benchmark.

It is a research tool. It must not produce trading signals or investment advice.

## 1. Non-negotiable rules
1. The `publish_time <= as_of` filter is applied in the Chroma query (`where` clause), never in Python after retrieval.
2. Sentiment, event-study, and verifier code must also take `as_of` and ignore later data.
3. All numbers in answers come from tool functions. The LLM never computes or invents figures.
4. Fixed pipeline of plain functions. No agent frameworks (no LangChain agents, AutoGen, etc.).
5. Fixed random seeds (`SEED = 42`), pinned `requirements.txt`, config in `config.yaml`.
6. Cache everything expensive (embeddings, FinBERT scores, LLM outputs) to disk.
7. All timestamps are UTC. Store `publish_time` as integer epoch seconds.
8. Write type hints, docstrings, and a pytest test for every module.
9. Never delete or weaken: the as-of filter, the leakage test, the event study, the baselines.

## 2. Tech stack
Python 3.10+, pandas, numpy, datasets (Hugging Face), yfinance, sentence-transformers (`BAAI/bge-small-en-v1.5`), chromadb, transformers + torch (`ProsusAI/finbert`), statsmodels, scipy, plotly, streamlit, pytest, pyyaml, tqdm. LLM: provider-agnostic wrapper in `llm.py` (API model or local Ollama), selected via config and used ONLY for query parsing and narrative writing.

## 4. Phases

### Phase 1: Setup and data prep (minimal, one-time)
Goal: get ready-made data with as little processing as possible.
- Create the structure, `requirements.txt`, `config.yaml` (tickers, date range, index symbol, alpha, half-lives, model names, SEED).
- `data_prep.py`:
  - Load the FNSPID financial news dataset from Hugging Face (inspect its columns first, then map). Filter to the 4 chosen tickers (config; pick large US caps with dense news coverage, e.g. AAPL, MSFT, NVDA, AMZN, but confirm they have enough documents per week) and a 2-year window.
  - Normalize to schema: `doc_id, ticker, text, publish_time (UTC epoch int), source_type, source_name`. Drop empty/duplicate texts. Save `data/processed/docs.parquet`.
  - Download daily OHLCV with yfinance for the 4 tickers plus the index (`^GSPC` or `SPY`). Save `data/processed/prices.parquet`.
  - Get earnings dates (yfinance) into `data/processed/earnings.parquet`. If unavailable, skip; detect events from large moves instead.
  - Print a summary: documents per ticker per month, date range, missing weeks.
- Do NOT scrape. Do NOT ingest social media or SEC filings.
- Acceptance: parquet files exist, schema validated by a test, summary printed, no ticker has many empty weeks (report if it does).

### Phase 2: Embeddings and vector index
- `embed_index.py`: embed all docs with BGE-small in batches (GPU if available), cache embeddings to disk, build a persistent Chroma collection with metadata `ticker`, `publish_time` (int), `source_type`, `source_name`.
- Idempotent: rerunning does not duplicate.
- Acceptance: collection count equals the doc count; a test queries with `where={"publish_time": {"$lte": X}}` and asserts every returned doc satisfies it.

### Phase 3: Retrievers (core novelty)
In `retrieval.py` implement three retrievers with a common interface `retrieve(query, ticker, start, end, as_of, k) -> list[Doc]`:
1. `PlainRetriever`: vector similarity only (no as-of filter, no time logic).
2. `RecencyRetriever`: similarity plus recency weighting, no as-of filter, no stratification.
3. `TemporalRetriever`:
   - Apply the as-of filter in the Chroma `where` clause, combined with ticker and `[start, min(end, as_of)]`.
   - Fetch the top 50 candidates, re-score with `score = alpha * similarity + (1 - alpha) * decay`, `decay = exp(-ln2 * age_days / half_life)`, age measured relative to `as_of`; half-life per `source_type` from config.
   - Window-stratified: split the window into monthly buckets, take the top-n per bucket, merge, sort.
   - Toggles `use_decay` and `use_stratification` (needed for ablations) and `use_asof_filter`.
- Acceptance: tests prove (a) no doc after `as_of` is ever returned by the temporal retriever for many random as-of dates; (b) stratified results cover every non-empty month; (c) plain/recency retrievers can return post-as-of docs.

### Phase 4: Analytics tools
- `sentiment.py`: run FinBERT once over all docs (score = P(pos) - P(neg)), cache to `data/cache/sentiment.parquet`. Function `weekly_sentiment(ticker, start, end, as_of, min_docs)` returns weekly mean, doc count, and a `low_confidence` flag. Only uses docs with `publish_time <= as_of`.
- `events.py`: events = earnings dates plus days with |return| > 3 std. Map news published after market close to the next trading day. Only events on or before `as_of`.
- `event_study.py`: market model `R_stock = a + b * R_index` via statsmodels OLS on trading days [-120, -20] relative to the event. AR, CAR over [-1,+1] and [0,+5], t-statistic. Fallback: market-adjusted return. Refuse (return `None` with a reason) if the event window extends past `as_of` or there is not enough estimation data.
- Acceptance: unit tests with synthetic returns where the true AR is known; as-of tests confirm nothing later is used.

### Phase 5: Query parsing, orchestration, verifier
- `llm.py`: thin wrapper with disk caching keyed by prompt hash and temperature 0.
- `query_parser.py`: LLM extracts JSON `{ticker, start_date, end_date, as_of, intent}`; intent in `trend | event_impact | point_lookup`. Validate with a schema; if `as_of` is missing, default to `end_date`.
- `pipeline.py`: fixed chain per intent:
  - trend: temporal retrieval, weekly sentiment, narrative.
  - event_impact: events, event study, supporting docs, narrative.
  - point_lookup: latest relevant doc before `as_of`, answer.
  - Output: sentiment timeline data, event-impact table (event, date, CAR, t-stat, sources), narrative with dated citations. The narrative prompt receives only tool outputs and retrieved docs, and must cite `doc_id` and date.
- `verifier.py`: (a) every number in the narrative matches a tool output within rounding tolerance; (b) every citation exists and has `publish_time <= as_of`. On failure, regenerate once with failures listed; flag remaining unsupported sentences.
- Pipeline must accept `retriever=` so baselines can be swapped in.
- Acceptance: end-to-end test on a sample question per intent; verifier tests with deliberately wrong numbers and fake citations.

### Phase 6: Leakage test (headline result)
- `leakage_test.py`: create 20-30 synthetic future-dated documents with distinctive checkable content (e.g. a unique fictional product name or acquisition), inserted with `publish_time` after the chosen as-of dates. Mark them in metadata (`is_injected=True`) in a SEPARATE test collection copy so the main index stays clean.
- Run queries at 20 different as-of dates for all three systems.
- Measure retrieval leakage rate (any post-as-of doc in context) and answer leakage rate (answer mentions injected content, via keyword check).
- Output `results/leakage.csv` and a bar chart.
- Acceptance: T-RAG retrieval leakage is exactly 0; baselines reported honestly whatever they show.

### Phase 7: Temporal QA benchmark
- `benchmark.py`: auto-generate 40-60 questions with computed ground truth: trend (~15, from weekly sentiment), event impact (~15, from event study), point-in-time (~15, latest doc before as-of), optional comparison (~10).
- Split off a small dev set (about 10 questions). Tune `alpha` and half-lives on dev only, freeze in `config.yaml`, then run the full benchmark ONCE per system.
- Metrics: leakage rate, temporal retrieval accuracy, time-window coverage, numeric accuracy (within tolerance), citation validity, latency and tokens per query.
- Output `results/benchmark.csv`.

### Phase 8: Ablations
- `ablations.py`: rerun the benchmark with no as-of filter, no decay, no stratification, no verifier (one at a time). Output `results/ablations.csv` and a table.
- Extra honest check: correlation between weekly sentiment change and abnormal returns, reported even if weak.

### Phase 9: Streamlit demo (lowest priority)
- `app/streamlit_app.py`: question box, as-of date picker, a toggle for plain RAG vs T-RAG, Plotly sentiment timeline annotated with events, event-impact table, narrative with citations, and a highlighted warning if any retrieved doc is after `as_of`.

### Phase 10: Reproducibility and report support
- `scripts/run_all_eval.sh` regenerates all results from scratch.
- `README.md`: setup, how to run each phase, results summary, limitations (parametric LLM leakage not controlled; small set of companies and one period; not investment advice).
- Export figures and tables into `results/` for the report.
